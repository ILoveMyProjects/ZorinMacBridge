# 0.15.40 Pre-login Input Control Isolation Acceptance

TARGET slice: after cold reboot and the physically verified LoginWindow first frame, a rejected pointer event must never prevent later keyboard/control packets from being processed. Quartz remains a diagnostic fallback only; `CGEventPost` return success is not proof of LoginWindow delivery.

## Required physical log sequence

For the known MacBook failure, one LoginWindow session should show:

1. `Pre-login input check: corehid ... result=FAIL_OPEN` when the managed CoreHID path is unavailable.
2. `Pre-login input check: iohidsystem ... result=OPEN_READY [SELECTED]`. This means **armed**, not delivery-proven.
3. First pointer attempt may report `iohidsystem ... DISPATCH_FAIL rc=-536870207 (0xe00002c1)`.
4. The same pointer channel reports `quartz-async ... DISPATCH_PENDING`, then one of:
   - `DISPATCH_ACCEPTED_UNVERIFIED` if `CGEventPost` returns, or
   - `DISPATCH_TIMEOUT` if the native call does not return within the bounded watchdog.
5. While that Quartz pointer attempt is pending or timed out, a real key must still produce a Mac-side keyboard dispatch result. A pointer failure must never remove the still-open IOHIDSystem keyboard route.

## PASS

- control/TLS/video remain connected after pointer `0xe00002c1`;
- later keyboard TX produces a corresponding Mac dispatch result instead of disappearing;
- no synchronous Quartz call can block the pre-login control loop;
- pointer failure/fallback/timeout diagnostics are visible even inside the normal 0.5-second pointer-log window;
- Linux distinguishes `input armed` from `remote input active`;
- successful macOS password login still triggers the existing LoginWindow→Aqua handoff.

## FAIL

- client continues logging keyboard TX but no Mac dispatch result appears after the first pointer failure;
- Quartz timeout disconnects Desktop/video;
- `OPEN_READY` alone is described as verified remote input;
- any P0, LoginWindow capture, pairing/TLS, wake/display, or normal Aqua behavior regresses.

The full project TARGET remains physically unverified until one real reboot proves image + keyboard + mouse + password login + Aqua handoff.
