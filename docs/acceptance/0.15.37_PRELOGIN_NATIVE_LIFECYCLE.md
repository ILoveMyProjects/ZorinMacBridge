# 0.15.37 Pre-login Native Lifecycle Acceptance

Physical reboot acceptance is evidence-driven. No setup/pairing repetition is required.

Expected sequence on one LoginWindow video connection:

1. `runtime-version=PASS`.
2. `Pre-login capture progress: native-runner-starting`.
3. `Pre-login capture progress: native-runner-started`.
4. `Pre-login capture progress: native-run-enter`.
5. `Pre-login capture progress: capture-matrix-start`.
6. At least one `Pre-login capture backend: ...` row.
7. Either a decoded first H.264 frame, or explicit failure/progress for every supported capture candidate.

Replacement/timeout acceptance:

- a client-side first-frame timeout must cancel the stale server read without waiting only for TCP/TLS close;
- a following video authentication must not fail with `previous video session did not stop within 4s after forced socket shutdown`;
- normal Aqua/sleep-wake capture behavior is unchanged.

Native artifact acceptance:

- frozen app self-test must report the embedded native streamer version;
- the embedded dylib version must equal the application release version;
- a mismatch is a hard error, not a warning.

Final TARGET remains unverified until a physical reboot reaches LoginWindow first frame, verified input delivery, password login, and Aqua handoff.
