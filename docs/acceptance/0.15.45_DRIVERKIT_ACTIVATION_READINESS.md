# 0.15.45 DriverKit activation/readiness acceptance

TARGET: preserve the verified cold-reboot LoginWindow video path and make the Mac-side DriverKit virtual keyboard/mouse become the only production pre-login input path.

Expected cold-reboot evidence:

1. TLS/auth and LoginWindow endpoint PASS.
2. ScreenCaptureKit persistent capture produces the first H.264 frame (unchanged from 0.15.44 physical PASS).
3. DriverKit may initially report `STARTING`, but the selected backend remains `driverkit`; IOHIDSystem/Quartz must not be selected merely because the DriverKit devices are still publishing.
4. DriverKit state must expose `driver_activated`, `driver_connected`, `keyboard`, and `pointing`.
5. When keyboard and pointing become true, the client receives `OPEN_READY`; the first accepted HID report changes the backend to `ACTIVE`.
6. Mouse and keyboard must operate the real macOS LoginWindow, password entry must complete, and normal Aqua handoff must follow.

Setup gate:
- The bundled signed virtual-HID package must be installed.
- The System Extension must report `[activated enabled]`.
- Daemon socket presence alone is not a PASS.
- `--self-test-virtual-hid` must observe both virtual devices ready.

Physical acceptance remains required; source/unit tests do not substitute for the cold-reboot LoginWindow test.
