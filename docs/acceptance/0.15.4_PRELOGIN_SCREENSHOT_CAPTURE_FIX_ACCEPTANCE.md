# ZorinMacBridge 0.15.4 — Pre-login Screenshot Capture Fix acceptance

## TARGET

After a full Mac reboot with no Aqua user session, the Zorin client must receive and render the macOS LoginWindow before remote input is enabled.

## Real-device acceptance

1. Install/update both the Linux client and the Mac server to 0.15.4.
2. Reboot the Mac and do not log in locally.
3. In Zorin discovery confirm the Mac reports `v0.15.4`.
4. Connect Desktop.
5. Confirm the client log reaches `Authentication successful for role='video'` and then `First H.264 frame decoded: ...`.
6. Confirm the macOS login window is visibly rendered in the Zorin Desktop canvas.
7. Confirm there is no repeated `previous video session did not stop within 20s` loop.
8. Move/click/type only after the first frame is visible. Confirm an input error, if any, does not tear down the Desktop session.
9. Log in remotely and confirm the client hands off to the normal Aqua desktop.

## Failure diagnostics

- `Screen Recording is not granted ... LoginWindow session` means TCC is blocking capture; 0.15.4 must report this explicitly rather than showing an unexplained black canvas.
- `prelogin-screenshot-error` in the Mac log identifies SCScreenshotManager failure.
- Absence of `First H.264 frame decoded` after successful video authentication means the pre-login capture path still has not delivered a usable sample.

## Environment limitation

The real LoginWindow ScreenCaptureKit and input behavior cannot be physically validated in Linux CI/container tests and must be verified on the target Mac.
