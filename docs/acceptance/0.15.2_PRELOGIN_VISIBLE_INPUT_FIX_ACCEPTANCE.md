# ZorinMacBridge 0.15.2 — Pre-login Visible/Input Fix acceptance

## Target

After a normal macOS reboot, before the target user has an Aqua session, the Zorin client must display the real macOS login window and keep the Desktop session alive while the user moves/clicks/types. After login, the normal Aqua Desktop must take over.

## Preconditions

1. Install/update the Linux client to 0.15.2.
2. Update the **Mac server** to 0.15.2 as well. This fix changes the macOS native streamer/input bridge; client-only update is insufficient.
3. In LAN discovery confirm the selected Mac reports `v0.15.2`. Do not accept `v0.14.18`/older for this test.
4. Existing System pairing and ZMB session password remain valid.

## Real-device acceptance

1. Reboot the Mac and do not touch its keyboard/trackpad.
2. On Zorin, wait for `system online`/pre-login availability and press Connect.
3. PASS only if the Linux viewer receives a visible login-window image and the log contains `First H.264 frame decoded`.
4. Move the pointer and click the login field. PASS only if the Desktop connection remains alive (no reconnect loop).
5. Type the macOS login credential and submit it. PASS only if loginwindow accepts the remote input.
6. After Aqua starts, PASS only if ZorinMacBridge automatically reconnects/continues to the normal Desktop session.

## Failure evidence to collect

If any step fails, collect both Linux client logs and `/var/log/zorinmacbridge-prelogin.log` plus `/var/log/zorinmacbridge-prelogin.err`. The Linux log should distinguish `waiting for first frame` from an input rejection.

## Not claimed by source tests

Static/unit tests verify the first-frame status handling, input gating, per-event failure isolation, and Quartz fallback wiring. They cannot prove that macOS 27 accepts synthetic pre-login input on the target M1. The real-device sequence above is authoritative.
