# 0.15.44 — Mac virtual HID LoginWindow acceptance

TARGET slice: keep the existing Zorin network input transport and physically
verified LoginWindow video path, but terminate keyboard/mouse input on the Mac
as a driver-backed virtual HID keyboard and relative pointing device.

## Source/CI acceptance

- `driverkit` is the first `LoginWindowInput` backend.
- The virtual-HID daemon socket is root-only and ZMB pre-login already runs as root.
- Client protocol version is 7.
- Keyboard initialization uses the upstream v8.x ABI: three uint64 values.
- Keyboard report is 67 bytes: report id, modifiers, reserved, 32 uint16 usages.
- Pointing report is 8 bytes: 32-bit buttons plus X/Y/vertical/horizontal wheel bytes.
- Relative movement larger than one signed report is split without loss.
- Installer bundles the pinned signed virtual-HID package and requests activation.
- A root LaunchDaemon keeps the virtual-HID daemon alive across reboot.
- Pre-login readiness requires virtual-HID input readiness plus current capture proof.
- Existing capture/TLS/pairing/wake/Aqua input are not replaced.

## Physical Mac acceptance

After the one-time driver-extension activation has completed:

1. Reboot to the normal macOS LoginWindow.
2. Zorin discovers/connects without re-pairing.
3. The real LoginWindow H.264 frame is visible.
4. Logs select `backend=driverkit` with keyboard and pointing ready.
5. Moving the Zorin pointer visibly moves the LoginWindow cursor.
6. Click selects the password field/account.
7. Typing from Zorin enters the password; Enter submits it.
8. macOS logs into Aqua.
9. Existing LoginWindow -> Aqua handoff reconnects normal ZMB Desktop.
10. A second reboot repeats steps 2–9 without reinstalling or re-pairing.

Physical PASS is not claimed until those steps are observed on the target Mac.
