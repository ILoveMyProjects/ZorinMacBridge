# ZorinMacBridge 0.15.33 — reboot LoginWindow evidence matrix

## TARGET

One physical reboot must be enough to determine, without guessing, whether the Mac can be remotely logged in from the already-paired Zorin laptop:

`reboot -> LoginWindow -> ZMB TLS/control -> real login screen -> remote keyboard/mouse -> password -> Aqua handoff`

The already-working sleep/wake display recovery and LoginWindow ScreenCaptureKit/VideoToolbox capture path are not replaced by this release.

## Checks performed after reboot

The normal client connection produces evidence for these checks in order:

1. **System reachability / endpoint** — the paired Mac is reachable on the existing LAN endpoint.
2. **TLS identity** — TLS 1.3 is established and the stored fingerprint is verified.
3. **Desktop authentication** — the existing ZMB session password authenticates the `desktop` role.
4. **LoginWindow ownership** — the server reports `prelogin=true` and issues the pre-login control token.
5. **Capture display** — the physical LoginWindow display is selected; the existing display-wake recovery remains available if ScreenCaptureKit initially reports no display.
6. **Capture first frame** — ScreenCaptureKit -> VideoToolbox -> ZMB transport -> client decoder must produce a real first H.264 frame.
7. **CoreHID input** — exact CoreHID backend open, observed Shift down/up, observed pointer move+restore.
8. **IOHIDUserDevice input** — exact IOHIDUserDevice backend open, observed Shift down/up, observed pointer move+restore.
9. **IOHIDSystem input** — exact IOHIDSystem/IOHIDPostEvent backend open, observed Shift down/up, observed pointer move+restore.
10. **Quartz input** — exact `kCGSessionEventTap` backend, observed Shift down/up, observed pointer move+restore.
11. **Backend selection** — only a backend with observed keyboard delivery may be selected. A backend with both keyboard+pointer PASS is preferred.
12. **Real password entry** — the user types the macOS password remotely; this is the final proof that the selected backend reaches the secure LoginWindow field.
13. **Aqua handoff** — after successful macOS login, ZMB must notify the client and hand off to the normal Aqua Desktop path without physical access to the Mac.

## Client log markers

The Zorin client reports the matrix without requiring a second setup or pairing pass. Expected markers include:

```text
Pre-login reboot checks: TLS/auth=PASS, LoginWindow endpoint=PASS; awaiting capture first frame and native input delivery matrix.
Pre-login input check: corehid ... keyboard=... pointer=... result=... [checked|SELECTED].
Pre-login input check: userdevice ... keyboard=... pointer=... result=... [checked|SELECTED].
Pre-login input check: iohidsystem ... keyboard=... pointer=... result=... [checked|SELECTED].
Pre-login input check: quartz ... keyboard=... pointer=... result=... [checked|SELECTED].
Pre-login reboot check: capture/video first frame=PASS (...).
```

A send API returning zero is not treated as proof. `keyboard=PASS` requires the Shift modifier transition to be observed in the combined LoginWindow session. `pointer=PASS` requires an observed cursor movement and restore.

## Interpretation

- `PASS` — keyboard and pointer delivery were both observed.
- `KEYBOARD_ONLY` — password entry may be viable, but pointer delivery was not proven.
- `FAIL_OPEN` — that exact backend could not be created/opened.
- `FAIL` — the backend opened or accepted reports but delivery was not observed.
- `SELECTED` — the backend chosen for production events in this LoginWindow control session.

If no backend proves keyboard delivery, the Desktop control and video channels remain alive. This is deliberate: diagnostics must remain visible instead of turning an input failure into a reconnect loop.
