# 0.15.39 Pre-login Input + Aqua Handoff Acceptance

TARGET slice: after the physically verified LoginWindow video first frame, remote keyboard/mouse must be observable end-to-end and a successful macOS login must cause an automatic handoff to the normal Aqua server.

## Input transport evidence

On one reboot/LoginWindow session, the Linux log must show both sides of each real input attempt without exposing password characters:

- client TX: `Pre-login keyboard TX: action=... category=modifier|printable|special` or `Pre-login mouse TX: action=...`;
- Mac dispatch result returned over `SESSION_STATE`: `Pre-login keyboard dispatch: ... backend=... result=... rc=...` or `Pre-login mouse dispatch: ...`;
- keyboard log entries MUST NOT contain keysyms, characters, text payloads, clipboard content, or password bytes;
- pointer movement logging is rate-limited so normal mouse movement does not flood the log.

For the physical 0.15.38 failure where IOHIDSystem pointer dispatch returned `0xe00002c1`:

1. IOHIDSystem remains available for keyboard input.
2. Pointer movement uses the relative IOHIDSystem path.
3. If pointer dispatch still fails, only the pointer channel may use direct Quartz fallback; the keyboard route must not be demoted solely because the pointer failed.
4. If keyboard dispatch itself fails, the existing bounded keyboard backend failover is still exercised and reported.

## Aqua handoff evidence

After a successful macOS password login, the pre-login helper must detect Aqua from either:

- a non-LoginWindow owner of `/dev/console`, or
- a live target-user `launchctl gui/<uid>` bootstrap domain.

PASS requires a log such as:

`[prelogin/handoff] Aqua session detected user=<user> source=/dev/console`

or:

`[prelogin/handoff] Aqua session detected user=<user> source=launchctl gui/<uid>`

followed by the existing handoff state, shutdown of the LoginWindow listener, and reconnection to the normal Aqua Desktop server. Repeated pre-login capture restarts after Aqua exists are FAIL.

## Regression contract

- P0 boot supervision is unchanged.
- The 0.15.37/0.15.38 LoginWindow ScreenCaptureKit/VideoToolbox path is unchanged.
- Normal Aqua capture and sleep/wake recovery remain unchanged.

The full TARGET remains unverified until real hardware proves keyboard delivery, mouse delivery, password login, and automatic Aqua handoff in one reboot flow.
