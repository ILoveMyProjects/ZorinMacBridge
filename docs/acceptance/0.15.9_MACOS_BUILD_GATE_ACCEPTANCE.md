# ZorinMacBridge 0.15.9 — macOS native build gate acceptance

## TARGET

A source push or pull request must fail before release if the native macOS input/streamer code does not compile on the supported Apple-Silicon GitHub runners. A tagged release must be blocked by the same gate before the macOS package is built or published.

## Required checks

1. Push or open a pull request and confirm the **macOS native build (macos-26)** job passes.
2. Confirm the **macOS native build (xcode-27)** job passes.
3. In both jobs, verify the log prints the macOS, Xcode, Swift and Clang versions.
4. Verify `scripts/verify-macos-native-gate.sh` builds `build/libzmb_streamer.dylib` through `scripts/build-macos-streamer.sh`.
5. Verify the gate checks that the dylib is arm64, links ScreenCaptureKit, VideoToolbox, CoreGraphics and IOKit, and exports the ZMB streamer/input ABI symbols.
6. Deliberately introduce an invalid Swift symbol on a test branch and confirm at least one macOS native build job fails before tagging. Revert the test change afterwards.
7. For a tag/workflow-dispatch release, confirm `macos-native-gate` completes before `macos-arm64` starts.
8. Confirm the macOS release build uses the same native gate script rather than a duplicate inline `clang`/`swiftc` command.

## STOP CONDITION

Do not publish a release when either `macos-26` or `xcode-27` native compilation is red. A green Linux test job alone is not sufficient for a release containing native macOS changes.
