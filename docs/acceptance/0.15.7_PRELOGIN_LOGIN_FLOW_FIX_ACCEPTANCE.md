# ZorinMacBridge 0.15.7 — PreloginLoginFlowFix acceptance

## TARGET

After a normal macOS reboot with FileVault not blocking boot, the Zorin client must be able to connect to the LoginWindow Desktop endpoint, receive a first H.264 frame of the physical login screen, keep the video session recoverable across disconnect/reconnect, and forward LoginWindow input without one rejected event tearing down the control channel.

## Automated acceptance

- `python3 -m compileall -q .`
- `scripts/run-tests.sh`
- `swiftc -frontend -parse native/macos/ZMBStreamerLib.swift`
- shell syntax checks for install/admin scripts
- plist parse checks
- workflow YAML parse checks
- release-source verification
- `git diff --check`
- patch apply check against clean 0.15.6
- full tests after patch
- patched tree equals final tree

## Real-Mac acceptance

1. Reboot the Mac to the normal macOS LoginWindow (not FileVault preboot).
2. Connect from Zorin.
3. Server log should identify `prelogin-capture-mode=cgdisplaystream` or, only if creation/start fails, `screenshot-manager-fallback`.
4. Client must log `First H.264 frame decoded` and visibly show LoginWindow.
5. Disconnect and reconnect. The next video connection must not report `previous video session did not stop within 4s`.
6. Click the password field and type a test character. The LoginWindow must react. If macOS rejects IOHID posting, the control session must remain connected and the server log must contain the rejected input event rather than disconnecting Desktop.
7. Enter the real macOS password and verify Aqua handoff/reconnect to the logged-in desktop.

## Boundary

The automated suite cannot prove macOS LoginWindow TCC/SecureEventInput behavior. Video and LoginWindow input remain real-device acceptance items. No VNC/Screen Sharing/port 5900 dependency is added.
